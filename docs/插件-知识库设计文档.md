# 插件-知识库设计文档

## 1. 文档范围

本文定义第一方 AI coding 插件在 DSH 协作台中选择项目知识库、按会话启用知识库和自动检索的行为。

项目、项目成员、项目到知识库的关联和 WeKnora 代理授权由 AI coding 服务端负责；Host 负责凭据、请求生命周期和 DSH 上下文装配；插件 UI 只呈现服务端返回的结果。

插件不直接访问 WeKnora，不保存 WeKnora 地址或凭据，不创建、编辑、导入、删除知识库，不管理文档、Chunk、Embedding、FAQ、Wiki 或 Graph。

管理后台的知识库页面见 [后台管理-知识库设计文档](https://github.com/STXR-1116/AI-coding-manage/blob/main/docs/%E5%90%8E%E5%8F%B0%E7%AE%A1%E7%90%86-%E7%9F%A5%E8%AF%86%E5%BA%93%E8%AE%BE%E8%AE%A1%E6%96%87%E6%A1%A3.md)，平台 API 见 [服务API-知识库需求文档](服务API-知识库需求文档.md)。项目选择与项目资产隔离规则见 [插件-项目管理设计文档](插件-项目管理设计文档.md)。

## 2. 产品对象和授权边界

知识库是与 Skill、Memory 和 Project 同级的项目资产。一个项目可以关联多个知识库，一个知识库可以复用到同一组织的多个项目；每条项目关联单独记录状态和修订号。

插件只展示服务端返回的项目知识库摘要。摘要包含平台生成的不透明 `knowledge_base_id`、名称、类型、处理状态、可检索能力和更新时间，不包含 WeKnora `kb_id`/`knowledge_id`、Token、原文、Chunk 或向量。

插件的有效访问是项目成员关系与平台知识库映射的交集。`admin` 和项目所属组织内的 `manager` 可以通过后台治理知识库，`member` 只能在明确的 active 项目成员关系成立时检索；插件不根据角色名称自行推导权限。

平台每次请求重新校验账号状态、组织范围、项目状态、项目成员关系、项目映射状态和 WeKnora 外部可用性。项目关联不能扩大知识库自身的组织或账号权限。

## 3. 协作台入口

用户登录后直接进入协作台。会话栏提供“知识库”按钮；按钮打开当前项目已关联且状态可用的知识库选择器，支持按名称过滤、全选和清空。

选择器按当前项目展示，不跨项目展示知识库。没有当前项目、项目为 draft、项目已归档或项目读取失败时，项目知识库区域显示空状态或服务失败状态，不显示上一个项目的内容。

选择器默认全部关闭。用户在当前会话显式开启一个或多个知识库后，后续每轮消息自动检索；选择状态只属于当前会话，刷新页面、新建会话、登出、账号切换和项目切换都会清空。

插件可以在选择器中显示 `processing`、`unavailable` 或 `no_index` 状态，但这些知识库不可开启。状态改变由服务端重新读取确认，不能根据旧的本地摘要推断可用。

## 4. 项目和选择状态

项目恢复沿用项目管理设计：Host 在重新认证并读取最新 active 项目列表后，按服务地址和 `user_id` 恢复唯一的不透明 `project_id`。知识库选择列表不写入浏览器持久化存储。

项目下拉框选择项目 B 时，Host 立即清空项目 A 的知识库选择、待处理检索、结果引用和错误状态，然后读取 B 的最新项目详情与知识库摘要。只有 B 读取成功后才允许打开知识库选择器。

并发读取使用当前选择序号或 AbortSignal 关联。旧项目的列表、检索或引用响应即使晚到，也不得覆盖当前项目的 UI 和会话上下文。

项目失权、项目归档、映射解除或服务端返回知识库 `403`/`404` 时，Host 清除当前项目的选择和结果，刷新项目列表；不自动切换其他项目，不使用旧结果或本地 Fixture。

## 5. 每轮自动检索流程

每轮用户消息只在当前会话至少开启一个知识库时触发检索。检索请求由 Host 发送到平台领域 API，插件不向 WeKnora 发请求。

请求使用 `POST /api/v1/projects/{project_id}/knowledge-search`，并显式携带用户查询、当前会话选中的平台知识库 ID 列表、结果上限和请求追踪信息。Host 自动附加访问令牌，项目 ID 只作为平台资源选择器。

平台重新鉴权后优先调用 WeKnora 原生 multi-KB hybrid-search；Embedding 能力不兼容时由平台按能力分组并行调用，再执行有限合并。插件不实现 RRF、Rerank、MMR、Chunk 去重或父子 Chunk 扩展。

检索响应为每个知识库分别返回 `used`、`no_hits` 或 `skipped`。`used` 表示有可用片段，`no_hits` 表示请求成功但没有命中，`skipped` 表示 processing、外部不可用、权限拒绝、超时或其他失败，并带可展示原因。

至少一个知识库为 `used` 时，Host 将所有成功片段和引用交给 DSH 模型；全部为 `no_hits` 时继续本轮并在引用区域显示“无相关内容”；部分 `skipped` 时继续本轮并标记“未使用 XXX 知识库”。

全部知识库均为 `skipped` 时，Host 阻断本轮模型请求，在会话栏显示逐项失败原因和重试入口。插件不把“没有知识库上下文”的请求当作成功。

## 6. DSH 上下文和引用

Host 把检索片段作为不可信资料上下文，使用明确的开始/结束分隔和来源字段，要求模型不得把资料内容解释为系统指令、工具授权或新的用户指令。

平台返回的标题、片段、来源 URL、知识库名称、资源 ID、分数和引用定位由 Host 转换为 DSH 会话可显示的引用。用户可以在引用抽屉查看来源并打开受授权的预览链接。

每轮模型可见的检索输入写入知识检索事件，包含查询、会话选中的平台知识库 ID、各知识库状态、资源 ID、受限片段、引用元数据和外部请求 ID。事件不写入项目 ID、WeKnora 凭据或 DSH 原生会话的项目授权字段。

项目 ID 不注入 DSH 原生 Session、系统提示词或全局配置。知识库片段也不复制到项目对象、Skill 安装记录或浏览器长期存储。

## 7. 请求生命周期和性能

正常多知识库检索只产生一次插件到平台的请求和一次平台到 WeKnora 的 multi-KB 请求。平台在 WeKnora 能力不兼容时才按兼容组并行请求，插件不执行 N+1 外部调用。

用户切换项目、停止生成或关闭会话时，Host 取消未完成的检索请求；迟到的响应依据请求序号丢弃。平台和 WeKnora 的超时、重试和限流由服务端策略控制，插件只呈现明确状态。

插件不落盘检索缓存，不跨会话或跨项目复用片段。会话内仅保留渲染所需的当前轮结果和可重建事件，项目切换立即丢弃前一项目的结果。

## 8. 错误处理

| 服务端结果 | 插件行为 |
|---|---|
| `401 AUTH_REQUIRED`、`TOKEN_EXPIRED`、`TOKEN_REVOKED` | Host 清理凭据并回到登录页，不保留知识库结果 |
| `403 FORBIDDEN` | 当前知识库标记 `skipped`；若仍有 `used` 结果则继续，否则按全部失败阻断 |
| `404 PROJECT_NOT_MEMBER`、`RESOURCE_NOT_FOUND` | 清除当前项目和选择状态，刷新项目列表 |
| `409 REVISION_CONFLICT` | 丢弃过期摘要，重新读取项目知识库列表，不显示本地成功 |
| `422 PROJECT_REQUIRED`、`VALIDATION_ERROR` | 显示请求错误并要求重新选择或修正输入 |
| `503 SERVICE_UNAVAILABLE`、网络错误或超时 | 对对应知识库标记 `skipped`，显示重试；所有知识库失败时阻断本轮 |

错误、诊断和性能日志只记录请求编号、阶段、耗时和错误码，不记录 Token、Cookie、密码、完整 Prompt、代码正文、本机绝对路径或 Git 地址。

## 9. Host 接口消费

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/me/projects/{project_id}` | 读取当前项目和可用知识库摘要 |
| `GET` | `/api/v1/projects/{project_id}/knowledge-bases` | 刷新当前项目知识库列表，适用于选择器打开和授权刷新 |
| `POST` | `/api/v1/projects/{project_id}/knowledge-search` | 每轮检索当前选中的知识库 |
| `GET` | `/api/v1/knowledge-bases/{knowledge_base_id}/documents/{document_id}/preview` | 使用平台不透明文档 ID 打开已授权引用的预览 |

所有请求由 Host 统一附加 Bearer Token、请求编号和取消信号。浏览器 UI 不读取或转发 Token；插件不接受客户端传入的用户 ID、WeKnora 租户 ID 或 WeKnora KB ID。

Host 已实现上述四个读取/检索方法的稳定 Remote 投影，并在项目切换时清空知识库选择、检索结果和错误状态；Client 保留显式检索入口，Host 同时通过 DSH 原生 `agent/pre-step` 在每轮模型请求前自动检索，使用 `knowledge-search` 会话事件记录模型可见输入和引用，并透传当前轮次的取消信号。

## 10. 验收场景

- 登录后直接进入协作台，当前 active 项目可打开知识库选择器，草稿、归档和不可见项目不出现。
- 一个项目选择多个知识库后，每轮消息只检索当前会话开启的集合，引用显示标题、片段、来源和知识库名称。
- 一个知识库不可用时，其他知识库仍能生成带部分引用的回答，并显示“未使用 XXX 知识库”。
- 全部知识库不可用时，本轮不发送 DSH 模型请求，用户能看到每个知识库的失败原因和重试入口。
- 项目切换会清空旧选择、结果和引用；旧响应不能覆盖新项目。
- 成员撤权、项目归档、映射解除或外部 KB 删除后，刷新立即隐藏知识库，不展示旧缓存。
- Token 不出 Host，项目 ID 不进入 DSH 原生会话，WeKnora ID 不出平台服务端。
- 服务失败、冲突和无权响应不会产生本地成功状态；检索事件和引用可按会话重建。
