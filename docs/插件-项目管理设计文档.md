# 插件-项目管理设计文档

## 1. 目的与边界

本文定义 `ai-coding-platform` 第一方插件如何读取项目、切换当前激活项目并使用项目关联资产。

项目、成员关系、资产关联、资产权限和未来云端任务由 AI coding 服务端负责；Host 只负责凭据和服务请求，UI 只负责呈现服务端结果。

本轮不实现项目创建、编辑、归档、成员管理、资产关联写入、代码源、任务、Run、Git、Workspace 或 DSH 原生会话上下文注入。这些能力由 Web 管理后台或后续模块负责。

## 2. 项目与权限

账号只有 `admin`、`manager`、`member` 三种全局角色，用户可以加入多个组织。

插件不根据角色名称计算资源权限，只渲染服务端返回的项目和资产摘要。`admin` 可使用服务端返回的全部 active 项目；`manager` 可使用其有效组织内返回的 active 项目；`member` 只有明确项目成员关系才可使用项目级资产。

项目必须同时满足项目访问授权和资产自身可见范围。项目关联不扩大 `platform`、`organization`、`project` 或 `account` 资产的原始权限。

## 3. 项目选择器

登录后插件直接进入协作台，不显示组织选择或项目选择门禁。

协作台左上角用户名右侧放置当前激活项目下拉框。下拉框按组织分组显示服务端返回的 active 项目，每项显示组织名称和项目名称，不显示草稿、归档或不可见项目。

登录并成功读取 `GET /v1/me/projects` 后，插件从浏览器受控存储读取上次的 `project_id`。存储键按服务地址和当前 `user_id` 隔离，只有该 ID 仍在最新 active 列表中时才恢复；否则删除记录并显示“选择项目”。

浏览器只保存不透明 `project_id`，不保存完整项目对象、资产列表、权限结果或上下文内容。项目 ID 不写入 URL，不通过 DSH 全局配置跨会话传播。登出、账号切换、会话失效或项目失权时清除对应记录。

进入项目详情不会改变当前激活项目；只有用户在下拉框中选择项目才会切换。项目详情是只读使用入口，不提供后台治理控件。

## 4. 项目中立状态和切换

登录账号没有可用 active 项目时，插件仍进入协作台。平台级、组织级和账号级资产按服务端授权正常展示；Skill、知识库和记忆等项目级资产区域显示“选择项目”空状态，不展示旧项目数据。

切换项目采用原子显示规则：

1. 用户选择项目 B 后，立即停止渲染项目 A 的项目级资产和操作。
2. Host 读取 B 的最新项目详情和授权资产摘要。
3. B 的读取成功后，插件渲染 B 的授权摘要并保存 B 的不透明 ID。
4. B 返回 `403` 或 `404` 时清除 B 和本地失效 ID，刷新项目列表，不自动替换为其他项目。
5. 其他失败只显示该资产或项目的失败状态和重试入口，不使用 A 的数据或本地 Fixture 冒充 B。

初次加载、窗口重新获得焦点、页面重新变为可见、账号抽屉中的“刷新访问范围”以及 Host/Skill 请求报告授权错误时重新读取服务端项目和访问摘要。打开下拉框本身和普通视图切换不额外发起项目列表请求。并发响应必须按当前选择的请求序号处理，旧项目响应不能覆盖新选择；当前项目详情请求只有收到项目专用的 `PROJECT_NOT_MEMBER` 或 `RESOURCE_NOT_FOUND` 时才清除失效项目并刷新列表，其他 `403` 保留为当前操作失败。

## 5. 项目详情和资产展示

项目详情使用 `GET /v1/me/projects/{project_id}`，只接收当前账号可见的项目基础摘要和三类资产非敏感摘要。当前插件的“项目”页展示项目基础摘要和只读说明，资产关系摘要由 Skill、知识库和记忆模块按授权 ID 各自消费，不在项目页重复展示资产正文。

项目摘要至少包含 `project_id`、`organization_id`、组织显示名、项目名称、`status`、更新时间和 `revision`。资产摘要至少包含 `asset_type`、`asset_id`、名称、`relation_kind`、更新时间和资产修订号。

`reference` 关系用于在项目资产区展示授权资产；`context` 关系标记为未来云端任务可选择的上下文候选。两者都不自动注入 DSH 原生会话，不把资产全文、知识片段、记忆内容、Prompt、代码或凭据复制到插件。

项目级 Skill 目录、安装和其他资产操作必须携带当前项目 ID。缺少项目 ID 时显示选择项目状态并处理 `PROJECT_REQUIRED`；不得使用第一个项目、上次项目或本地缓存替代。

平台级、组织级或账号级资产只有在 `access-summary` 返回相应摘要时才会出现在插件中；当前内存联调夹具只返回项目资产，因此没有当前项目时这些区域显示空状态。插件不能通过项目选择扩大这些资产的可见范围，生产资产模块接入后仍须执行自身授权过滤。

## 6. Host 和 API 消费边界

Host 管理访问令牌、Refresh Token、撤销和服务端请求，使用 DSH 原生 `ctx.authorization` / `ctx.credentials` 存储。浏览器 UI 永远不接触 Token。

插件所需的最小项目接口为：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/v1/me/projects` | 读取当前账号可见的 active 项目，支持游标分页和组织筛选 |
| `GET` | `/v1/me/projects/{project_id}` | 读取一个项目及当前账号可见的资产摘要 |
| `GET` | `/v1/team-skills?project_id={project_id}` | 读取指定项目可安装的已发布 Skill |
| `POST` | 现有 Skill 安装接口 | 请求体必须包含 `project_id`，由服务端再次鉴权 |

所有请求由 Host 附加 Bearer Token；项目 ID 仅作为服务端资源选择器，不是权限凭据。服务端每次请求重新校验账号状态、组织范围、项目状态、项目成员关系和资产权限。

当前 Host 对项目列表不传分页或组织筛选参数，直接消费服务端返回的 `items`；项目级目录、版本状态和安装授权请求显式携带 `project_id`。本地卸载只依据 Host 保存的 `local_installation_id` 定位已安装副本，不是服务端项目级请求；该副本最初记录的项目 ID 仍用于此前的发布状态授权。

## 7. 错误和隐私

| 服务端结果 | 插件行为 |
|---|---|
| `401 AUTH_REQUIRED`、`TOKEN_EXPIRED`、`TOKEN_REVOKED` | Host 清理凭据并回到登录页 |
| `403 ACCOUNT_SUSPENDED` | 清理会话并显示账号不可用 |
| `403 FORBIDDEN` | 当前操作显示无权失败，保留其他授权内容；不会把普通 `403` 当作项目失效自动替换项目 |
| `404 PROJECT_NOT_MEMBER`、`RESOURCE_NOT_FOUND` | 移除当前项目或资源，刷新最新列表 |
| `422 PROJECT_REQUIRED` | 要求用户先选择当前项目 |
| `503 SERVICE_UNAVAILABLE` 或网络错误 | 显示服务失败和重试，不使用旧权限结果 |
| `409 REVISION_CONFLICT` | 丢弃过期摘要并重新读取 |

日志和诊断只记录请求编号、阶段、耗时和错误码，不记录 Token、Cookie、密码、Prompt、代码正文、环境变量值、本机绝对路径或 Git 地址。

## 8. 插件验收

- 未登录时只显示登录页，项目和任何团队资产不加载。
- 多组织账号登录后直接进入协作台，下拉框按组织分组显示所有可见 active 项目。
- 刷新页面时只在服务端重新授权成功后恢复按账号隔离的项目 ID。
- 进入项目详情不切换当前项目；下拉框选择项目后才刷新项目资产。
- 未选择项目时不显示项目级资产；切换项目时旧项目资产不会短暂泄露。
- Skill、知识库和记忆只显示服务端授权摘要；撤权、归档或 `403/404` 后刷新即隐藏。
- 所有项目级请求携带 `project_id`，不向 DSH 原生会话注入项目上下文。
- 服务失败、冲突和无权响应均不产生本地成功状态。
